## 性能优化总览

### 已完成优化

| ID | 优化 | 改动文件 | 效果 |
|----|------|---------|------|
| P0 | 无锁 Bucket 访问 | `cuckoo.rs` | insert_lock_free/lookup_lock_free, &self 无 Mutex |
| P1 | Table 初始化加速 | `cuckoo.rs` | Vec::with_capacity+set_len, HugePage 预置零路径 |
| P2 | Lookup 快速路径 | `cuckoo.rs` | get_fast 内联 h1/h2, 跳过 ClientReader |
| SGE | WR 链表批量提交 | `qp.rs` + `ops.rs` + `opt.rs` | post_send_batch 单次门铃提交整条链 |

### 性能分析关键发现

1. **单线程 insert_lock_free 比 insert 快 5-9%**: 编译器优化收益（`&self` vs `&mut self`）
2. **并发优化无法在本地验证**: 本地多线程需要 Mutex，分布式场景每个 Client 独立 QP 天然无竞争
3. **HugePage 零初始化收益**在生产环境（OS 预置零页），本地测试未见差异
4. **CAS (SoftRoCE) 81ns**: 物理 mlx5 网卡预期 ~1-2μs，差距 12-25× 为软件模拟开销

## 当前性能基准

### 本地模拟模式（无 RDMA 硬件）

| 操作 | 延迟 | 备注 |
|------|------|------|
| Lookup h1 hit | 32 ns | 极速，单桶探测 |
| Inline insert | 58 ns | 小表无锁插入 |
| CAS (SoftRoCE) | 82 ns | 软件 RDMA，非物理性能 |
| Extent alloc | 435 ps | 小分配编译器优化后零开销 |
| Concurrent 8线程写 | 1.76 ms | Mutex 瓶颈（分布式不存在） |
